Backend Authentication & Authorization System

Это небольшое backend-приложение на Django + DRF, реализующее собственную систему аутентификации и авторизации. Основной целью проекта было продумать и реализовать механизм доступа к ресурсам без использования готовых возможностей Django для аутентификации и ролей.

Основные возможности
1. Работа с пользователем

Регистрация: пользователь указывает имя, фамилию, отчество, email и пароль.

Login / Logout: после входа пользователь получает токен, который используется для идентификации в последующих запросах.

Обновление профиля: пользователь может изменить свои данные и пароль.

Удаление аккаунта (мягкое): пользователь инициирует удаление, происходит logout, is_active=False. Аккаунт остаётся в базе, но залогиниться больше нельзя.

2. Система ролей и разрешений

Роли: admin (администратор с полным доступом) и user (обычный пользователь).

Права доступа: реализовано через таблицы Role, Permission, UserRole и RolePermission.

Админ может назначать роли другим пользователям и управлять разрешениями.

Любые запросы к админским API проверяют наличие роли admin. Если нет – возвращается 403 Forbidden.

Если пользователь не залогинен или токен некорректный – 401 Unauthorized.

3. Минимальные бизнес-объекты

Reports – простые объекты для демонстрации прав доступа.

Админ видит все отчёты.

Обычный пользователь может просматривать отчёты (без фильтрации по владельцу, т.к. в тестовом задании это не требовалось).

Важно: изначально планировалось сделать фильтр «пользователь видит только свои объекты, админ – все», но возникли трудности, поэтому оставлен упрощённый вариант для демонстрации.

Технологии

Django 5.x

Django REST Framework

PostgreSQL

Использование токенов

Пользователь получает собственный токен при login.

Токены временные, могут иметь срок действия.

Все защищённые эндпоинты требуют токен в заголовке:

Authorization: TOKEN <token>

API
Пользовательские

POST {{BASE_URL}}/api/users/register/ – регистрация

POST {{BASE_URL}}/api/users/login/ – login

POST {{BASE_URL}}/api/users/logout/ – logout -требуется токен доступа

PATCH {{BASE_URL}}/api/users/update/ – обновление профиля -требуется токен доступа

GET {{BASE_URL}}/api/users/me/ – просмотр своего профиля -требуется токен доступа

DELETE {{BASE_URL}}/api/users/delete/ – мягкое удаление аккаунта -требуется токен доступа

Админские

POST {{BASE_URL}}/api/permissions/admin/role/ – создание роли -требуется токен доступа и роль admin

POST {{BASE_URL}}/api/permissions/admin/user-role/ – назначение роли пользователю -требуется токен доступа и роль admin

DELETE {{BASE_URL}}/api/permissions/admin/user-role/ – снятие роли -требуется токен доступа и роль admin

GET {{BASE_URL}}/api/permissions/admin/user-role/ – получение всех ролей -требуется токен доступа и роль admin

Бизнес-приложение

GET {{BASE_URL}}/api/business/reports/ – список всех отчетов (только для админа) -требуется токен доступа

GET {{BASE_URL}}/api/business/reports/all/ – список всех отчетов (для всех пользователей) -требуется токен доступа

Установка и запуск

Клонируем репозиторий

git clone <URL_репозитория>
cd <название_папки>


Создаём и активируем виртуальное окружение

python -m venv venv
# Windows
venv\Scripts\activate
# Linux / Mac
source venv/bin/activate


Устанавливаем зависимости

pip install -r requirements.txt


Настраиваем базу данных

Данные БД и секретный ключ хранятся в файле .env.

Применяем миграции

python manage.py migrate


Загрузка фикстур (в правильном порядке!)

python manage.py loaddata admin_user.json
python manage.py loaddata roles.json
python manage.py loaddata user_roles.json


Фикстуры создают базового администратора, роли и привязку ролей к пользователю.

Запуск сервера

Переходим в src
cd src
python manage.py runserver
